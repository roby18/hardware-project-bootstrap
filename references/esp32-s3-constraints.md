# ESP32-S3 芯片侧约束速查（用于反查厂家引脚表）

用途：把用户收集到的板级引脚拿来与下表交叉核对，发现冲突立即在硬件档案中标红。
**适用 ESP-IDF 5.x / ESP32-S3；电平语义与封装差异以该批次芯片 datasheet 与 TRM 为准，本文档只做第一轮筛查，不替代官方手册。**

## 引脚总览（易踩坑）

- 可用 GPIO 为 **GPIO0–GPIO21 与 GPIO26–GPIO48，共 45 个**。**GPIO22–GPIO25 在芯片上不存在**，工程里出现这几个编号必然是错误。
- 所有 GPIO 默认 **3.3V 电平，不耐 5V**；5V 外设必须加电平转换或隔离。
- 单脚可配置驱动能力（默认约 20mA，最大约 40mA 档），但总功耗仍受 LDO 与电源轨限制。
- 模组上未引出的脚即使在芯片上存在也不能使用——以模组 Pinout 为准。

## Strapping 引脚（启动瞬间被采样，挂载外设必须评估）

| 引脚 | 启动采样作用 | 设计约束 |
|---|---|---|
| GPIO0 | 启动模式选择（拉低进入下载模式） | 必须有可靠上拉；常接 BOOT 键到 GND；挂外设时不得在上电瞬间把它拉低 |
| GPIO3 | JTAG 信号源选择 | 上电默认电平会影响 JTAG 来源；外围不要强行驱动 |
| GPIO45 | VDD_SPI 电压选择（决定内部 Flash 工作 1.8V/3.3V） | 模组已按 Flash 类型固定偏置；**禁止当普通输出随意拉低**，可导致无法启动 |
| GPIO46 | ROM 信息输出控制（启动日志开关相关） | 启动期间外围不得强拉；具体可用方向以 datasheet/模组手册为准 |

共性纪律：这四个脚上的外设，上电瞬间的电平必须与正常启动要求一致；上下拉阻值要压过外设漏电。

## 被片上存储占用（禁止外配）

- **GPIO26–GPIO32**：连接内部 SPI Flash，任何模组都不可用。
- **GPIO33–GPIO37**：带 Octal PSRAM 的模组连接 PSRAM，不可用；无 Octal PSRAM 时也以模组手册为准，不要默认空闲。

## 常用固定功能脚

| 功能 | 引脚 |
|---|---|
| USB D- / D+（USB-OTG / USB-Serial-JTAG 复用） | GPIO19 / GPIO20 |
| UART0 默认 TXD / RXD（启动与日志） | GPIO43 / GPIO44 |
| 外部 JTAG：MTCK / MTDO / MTDI / MTMS | GPIO39 / 40 / 41 / 42 |
| ADC1 通道范围 | GPIO1–GPIO10 |
| ADC2 通道范围 | GPIO11–GPIO20（**与 Wi-Fi 并发使用受限**，需要采样时可能采不到） |
| 触摸传感 | GPIO1–GPIO14 |
| RTC/深睡眠可用脚 | GPIO0–GPIO21（RTC GPIO） |

排查要点：
- 想用串口日志时，不要把 43/44 分给其他外设，除非显式重映射日志 UART。
- 板子用原生 USB 下载/调试时，19/20 不能再做普通 GPIO。
- 电池类模拟采样优先放 ADC1，避免 Wi-Fi 工作时 ADC2 读不到。
- 深睡眠唤醒脚必须从 RTC GPIO（0–21）里选。

## 反查流程（每个外设在写进 board_pins.h 前过一遍）

1. 编号合法？是否落在 0–21 / 26–48？
2. 是否被 Flash/PSRAM 占用（26–37）？
3. 是否 strapping 脚（0/3/45/46）？若是，上电默认电平与外设有无冲突？
4. 是否与 USB（19/20）、日志串口（43/44）、JTAG（39–42）冲突？
5. 外设所需的外设功能（ADC/触摸/I2S/LCD/UART）在该脚上是否可用？查 IOMUX/GPIO Matrix 表。
6. 电平与电压域是否匹配？有没有 5V、1.8V 器件直连？
7. 启动瞬间默认态会不会让电机、功放、电源使能误动作？
8. 来源是否可靠：实测 > 原理图网络名 > 厂家例程宏 > 网络文章。任何冲突写进硬件档案「冲突记录」。

## 配套实测命令（板子在手时）

```powershell
# 读 Flash 容量/厂家/模式（在已激活 ESP-IDF 的终端，替换实际串口）
esptool.py --chip esp32s3 -p COMx flash_id

# 构建并烧录/监视（Windows 低并发，避免 1455 页面文件错误）
$env:IDF_PY_BUILD_JOBS='2'
idf.py -p COMx build flash monitor
```

看到的 Flash/PSRAM 信息回填到 `docs/hardware/board.md`；与资料不一致时以实测为准。
