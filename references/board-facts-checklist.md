# 板级事实核查清单（访谈用）

按 SKILL.md 的阶段取用，每次只问当前阶段的问题。每项记录**值**和**来源**。
来源分级：`实测` / `原理图` / `厂家资料` / `官方文档` / `网络（仅线索）`。任何无法确认的项写 `[unknown]` 并附获取动作。

## 阶段 0：项目意图

- [ ] 一句话产品目标
- [ ] 可观察的成功标准（演示时看到什么算成功）
- [ ] 非目标（本期明确不做的事，至少列 2 条）
- [ ] 既有契约依赖：App / 云 / 协议 / 外壳 / 已量产硬件（有则记录版本）
- [ ] 交付形态：裸板验证 / 小批量 / 量产（决定测试与标识严格度）

## 阶段 1：芯片与模组身份

- [ ] 芯片型号与封装（精确到子型号，如 ESP32-S3FN8 / ESP32-S3R8V）
- [ ] 模组完整型号（如 ESP32-S3-WROOM-1-N16R8）
- [ ] Flash 容量（MB、电压 1.8V/3.3V、Quad/Octal）
- [ ] PSRAM：无 / Quad / Octal，容量
- [ ] 实测命令输出：`esptool.py --chip <chip> flash_id`
- [ ] 晶振频率、天线形式（板载 PCB 天线 / IPEX 外接）
- [ ] 芯片修订版（ECO 版本，影响 errata）
- [ ] SDK 与精确版本（ESP-IDF vX.Y.Z / Arduino core 版本）
- [ ] 开发板厂家 + 板名 + 版本丝印 + 购买链接
- [ ] 原理图 PDF / 引脚图 / 厂家 Wiki / 官方例程仓库链接
- [ ] 板卡是否有多个版本（同一名称不同批次布线差异）

## 阶段 2：下载、供电与调试

- [ ] USB 接口连接方式：原生 USB（D+/D- 直连芯片哪两个脚）/ USB-UART 桥（芯片丝印型号）
- [ ] 有几个 USB 口，分别接什么
- [ ] 供电来源：USB 5V / VIN / 电池 / 外部稳压；板上 LDO 型号与输出能力（mA）
- [ ] 整机峰值电流估算（WiFi/BT 发射、外设同时工作）
- [ ] 3.3V 与 1.8V 电源域，哪些外设挂在哪一路
- [ ] BOOT 键、RESET 键接到哪个脚；有无自动下载/复位电路
- [ ] 拨码开关 / 跳线帽及其默认位置（拍照记录）
- [ ] 调试通道：USB-Serial-JTAG / 外接 JTAG（引脚）/ 仅串口日志
- [ ] 系统日志串口的 TX/RX 引脚与默认波特率

## 阶段 3：电源与危险区

- [ ] 共用电源轨 / 负载开关：使能脚、被供电的外设清单、使能有效电平
- [ ] 上电/掉电时序要求（谁先谁后、最小间隔）
- [ ] 上电瞬间必须保持的电平（防止误动作、反向供电、闩锁）
- [ ] strapping pin 上挂了什么（启动时外部电路不得与采样电平冲突）
- [ ] 可承受最大电压；有无电平转换（5V 外设 vs 3.3V MCU）
- [ ] 电池充电/反接保护、保险丝、热风险
- [ ] 天线净空区是否被外壳/线束遮挡
- [ ] Flash/PSRAM 占用引脚（这些脚禁止用于外设）

## 阶段 4：逐外设引脚事实

每个外设复制下表填写：

| 字段 | 内容 |
|---|---|
| 外设与型号 | |
| 信号名（总线.功能） | |
| GPIO | |
| 方向 | 输入 / 输出 / 双向 / OD |
| 上下拉 | 外部阻值 / 内部 / 无 |
| 上电默认态必须是 | |
| 电压域 | 3.3V / 1.8V / 5V+电平转换 |
| 特殊约束 | 启动电平、中断、映射能力（ADC/触摸/I2S 等） |
| 来源 | 原理图网络名 / 厂家例程宏 / 丝印 / 万用表实测 |

重点外设追问：

- [ ] LED：普通 LED 还是 WS2812/APA102 串行灯；颜色、限流电阻、有效电平、供电来源
- [ ] 按键：接通到 GND 还是 VCC；外部上下拉；按下/松开电平
- [ ] 旋转编码器：A/B 相、按键脚、有无外部消抖
- [ ] I2C：SCL/SDA、速率上限、所有从机**实测地址**（上机后用 i2c-tools/扫描固件确认）、上拉在哪一侧
- [ ] SPI：CLK/MOSI/MISO/CS（每个从机独立 CS）、最高速率、模式
- [ ] UART：TX/RX/CTS/RTS、波特率、对端电平
- [ ] I2S/音频：BCLK/WS/DIN/DOUT/MCLK、PDM 还是 TDM、功放使能与静音脚
- [ ] ADC：输入分压网络、量程、输出阻抗是否满足驱动要求
- [ ] 显示：接口类型、分辨率、驱动 IC、背光使能脚、复位脚
- [ ] SD/存储：占用脚、供电方式、热插拔
- [ ] 继电器/电机/大电流负载：驱动电路、续流、启停对电源的扰动
- [ ] 未使用但引到排针的脚：默认电平策略（避免悬空导致功耗/误触发）

## 阶段 5：通信与存储契约

- [ ] USB 设备模式（CDC/HID/MSC/Vendor）、VID/PID、设备名、序列号、对端兼容版本
- [ ] BLE：服务/特征值规划、配对要求、最大包长约束
- [ ] 自定义协议：报文格式（偏移/长度/字节序）、版本协商、超时、重传
- [ ] 分区表：各分区名/偏移/大小；标注「冻结」
- [ ] NVS 命名空间与键；出厂固件与升级路径
- [ ] OTA：双分区/回滚策略（如涉及）
- [ ] 凭据处理：禁止写入真实 Wi-Fi/密钥，说明烧录注入方式

## 阶段 6：构建环境

- [ ] 操作系统与内存大小
- [ ] SDK 安装路径（本工程归属的唯一一套，多版本共存时写明）
- [ ] 工具链路径、Python 环境
- [ ] 构建命令、全量/增量构建耗时
- [ ] Windows 低并发：`IDF_PY_BUILD_JOBS=2`（命令行）、插件 `idf.ninjaArgs ["-j","2"]`
- [ ] 页面文件位置与大小（16GB 内存机器建议 D 盘 8–24GB）
- [ ] 烧录命令与串口；烧录授权规则（人工确认）
- [ ] 监视器/日志查看方式
- [ ] 版本号规则与固件版本串存放位置

## 阶段 7：缺口分级

- [ ] 上板前必须补齐（不补齐就无法安全烧录的事实）
- [ ] 可边做边补（bring-up 中能实测得到、且不影响首次安全上电）
- [ ] 冲突事实记录：资料 vs 实测不一致项（一律以实测为准并注明）
